What

GDB, the GNU Project debugger, allows you to see what is going on `inside’ another program while it executes – or what another program was doing at the moment it crashed.

GDB can do four main kinds of things (plus other things in support of these) to help you catch bugs in the act:

  • Start your program, specifying anything that might affect its behavior.
  • Make your program stop on specified conditions.
  • Examine what has happened, when your program has stopped.
  • Change things in your program, so you can experiment with correcting the effects of one bug and go on to learn about another.

Example Usage

  • Set the architecture of the target
    • set architecture ARCv2
  • Connect to a remote debugger (like OpenOCD for example!)
    • target remote localhost:4444
  • Set a breakpoint at address 0x75C
    • b *0x75C
  • Examine registers
    • info reg
  • Step through the next instruction
    • stepi/si
  • Examining memory:
    • The x command lets you examine memory
    •   x [Address expression]
  x /[Format] [Address expression]
  x /[Length][Format] [Address expression]
    • The available formats include:
      • o - octal
      • x - hexadecimal
      • d - decimal
      • u - unsigned decimal
      • t - binary
      • f - floating point
      • a - address
      • c - char
      • s - string
      • i - instruction
    • Examine 10 bytes at address 0x7F00: x/10b 0x7F00
  • Disassembling instructions
    • Instructions can be disassembled with the i command:
    • To disassemble the isntructipon at the current PC register:
      • x/10i $pc
  • Dumping Memory:
    • GDB Can be used to dump memory to a file
    • dump memory OUTPUT_FILE START_ADDRESS SIZE
